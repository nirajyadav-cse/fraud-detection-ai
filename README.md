# 🛡️ AI Fraud Detection in Financial Transactions

A beginner-friendly machine-learning project that estimates suspicious transaction risk and displays predictions in a Streamlit dashboard.

> **Important:** This project uses **synthetic demo data**. It is for learning and portfolio demonstration only—not for real financial, compliance, or customer decisions. Predictions can be wrong.

## Features
- Train a Random Forest classifier on reproducible synthetic transaction data.
- Upload a CSV and score transaction-like records.
- View predicted labels and model probability estimates.
- Download prediction results as CSV.
- Download a sample CSV for testing.

## Run locally (Mac/Linux)
Python 3.11 or 3.12 is recommended.

1. Clone your GitHub repository and enter its folder:
   ```bash
   git clone https://github.com/YOUR-GITHUB-USERNAME/fraud-detection-ai.git
   cd fraud-detection-ai
   ```
2. Create and activate a virtual environment:
   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   ```
3. Install dependencies:
   ```bash
   python -m pip install --upgrade pip
   pip install -r requirements.txt
   ```
4. Train the demo model:
   ```bash
   python train_model.py
   ```
5. Launch the dashboard:
   ```bash
   streamlit run app.py
   ```

## Required CSV columns
All columns must be numeric.

| Column | Meaning | Example |
|---|---|---:|
| `amount` | Transaction amount | 125.50 |
| `time` | Hour of day, 0–23 | 14 |
| `merchant_risk` | Demo risk score, 0–1 | 0.35 |
| `distance_from_home_km` | Approximate distance from usual location | 12.5 |
| `failed_attempts_24h` | Failed attempts in last 24 hours | 1 |
| `is_international` | 1 if international, otherwise 0 | 0 |

Use **Download sample CSV** inside the app to get a correctly formatted example.

## Deploy on Streamlit Community Cloud
1. Push the project to a public GitHub repository.
2. Visit https://share.streamlit.io/ and select **Create app**.
3. Select your repository, branch `main`, and main file `app.py`.
4. Deploy; Streamlit installs dependencies from `requirements.txt`.
5. Copy the actual deployed URL into this README after deployment. Do not invent a demo URL in advance.

## Model limitations
The training data and labels are generated by a simple synthetic risk formula, not collected from banks. Metrics printed during training only demonstrate the code workflow; they do not establish real-world fraud detection performance. Do not use this model to block transactions or make real customer decisions. A real system requires suitable licensed data, rigorous validation, privacy/security controls, monitoring, and human oversight.
